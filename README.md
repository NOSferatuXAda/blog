# Creationism

个人博客源码，基于 **Hexo 8** + **NexT 8** 主题，经深度定制为「黑 / 红 / 灰 / 白 + Surreal 超现实」视觉风格，托管在 GitHub Pages。

- 🌐 线上地址：<https://nosferatuxada.github.io/blog/>
- 📦 仓库：<https://github.com/NOSferatuXAda/blog>
- 📘 完整改造文档：[docs/customize-guide.md](docs/customize-guide.md)（配置 / 页面 / CSS 全量代码 + Butterfly/Fluid 移植说明）
- 🚀 发布方式：源码在 `main` 分支，构建产物由 `hexo-deployer-git` 推送到 `gh-pages` 分支，GitHub Pages 从该分支发布。

## 当前定制内容

- **导航栏**：首页 / 分类 / 关于 / 致谢 四个核心类别。
- **首页**：静态落地页，仅三个展示栏区块，整体居中偏右排列（无文章列表）。
- **分类页**：父级「全部」+ 三个子项（公告 / 技术 / 日常），其中「公告」进入更新日志时间轴。
- **关于页**：纯占位页面。
- **致谢页**：用英文、中文、德文、Python、Java、C++ 六种语言表达「感谢」。
- **作者窗口**：侧边栏自定义个人信息卡片（头像、名字、简介、社交链接）。
- **视觉**：黑红灰白配色、锐利几何线条、错位硬阴影、红色几何水印。
- 所有尚未确定的内容统一使用 `unknown` 占位，方便后期精修。

## 更新日志（公告）

线上入口：**分类 → 公告**，或直接访问 <https://nosferatuxada.github.io/blog/logs/>。

规则：**每次对网页的可见修改，都要在 `source/_logs/` 新增一条 Markdown 日志**；页面会自动按 `date` 倒序生成时间轴（最新在最上）。

```powershell
# 新增一条日志（自动用当前时间命名）
powershell -File tools/new-log.ps1 -Title "本次改动标题" -Body "一两句话说明改了什么。"

# 也可以指定文件名与时间
powershell -File tools/new-log.ps1 -Title "..." -Slug "2026-11-01-some-change" -Date "2026-11-01 10:00:00"
```

日志 front-matter 模板：

```markdown
---
title: 更新标题
date: 2026-11-01 10:00:00
---

- 改动点 A
- 改动点 B
```

- `source/_logs/` 以下划线开头，Hexo 不会把它当普通页面/文章发布，只被 `{% logs %}` 标签读取。
- `/logs/` 页面正文只有 `{% logs %}`，时间轴由 `scripts/logs.js` 生成。
- 公告仓库与 `/archives/` 文章仓库完全分离。

## 最新公告自动弹窗

- **数据**：`/logs.json`（由 `scripts/logs.js` 生成，数组第一项即最新公告；包含 `version / title / dateText / content / url`）。
- **触发**：页面 `load` 后约 0.9s 请求一次 JSON；若 `localStorage` 中记录的版本号与最新 `version` 不同，则弹出。
- **关闭**：右上角 `×`、`Esc`、点击遮罩空白处；这些操作**不**写入 localStorage。
- **不再提醒**：左下角按钮，把当前 `version` 写入 `surreal-announcement-dismissed`；同版本不再弹出。
- **新公告**：`version` 由 `日期 + 标题/文件名 hash` 生成，新公告发布后版本变化，会重新弹出。
- **公告页排除**：`/logs/` 与 `/message/` 本身不弹窗，避免遮挡阅读与留言表单。
- **性能**：只请求一次小 JSON，弹窗显示/关闭无持续定时器，不参与背景动画的 rAF，实测弹窗打开时背景仍保持 60 FPS。

## 留言板（/message/）

- **入口**：首页第三栏「留言板」→ `/message/`。
- **前端文件**：
  - `source/message/index.html`：表单与列表结构
  - `source/js/message-board.js`：匿名/留名联动、校验、提交、列表渲染
  - `source/_data/styles.styl`：表单、开关、卡片样式
  - `source/_data/body-end.njk`：Supabase 配置 + 脚本引入
- **后端推荐**：Supabase（免费 Postgres + REST + RLS），适合自定义匿名字段，无需自建服务器。
- **演示模式**：`supabaseUrl` / `supabaseAnonKey` 留空时，留言只写入当前浏览器 `localStorage`，页面会显示演示提示，便于先验收 UI。

### Supabase 接入步骤

1. 在 <https://supabase.com> 注册并创建免费项目。
2. 打开 **SQL Editor**，执行：

```sql
create table if not exists public.messages (
  id bigint generated by default as identity primary key,
  name text,
  content text not null check (char_length(content) between 1 and 500),
  anonymous boolean not null default true,
  is_visible boolean not null default true,
  created_at timestamptz not null default now()
);

alter table public.messages enable row level security;

create policy "public can read visible messages"
  on public.messages for select
  using (is_visible = true);

create policy "visitors can insert messages"
  on public.messages for insert
  to anon
  with check (
    char_length(content) between 1 and 500
    and (
      (anonymous = true and name is null)
      or (anonymous = false and name is not null and char_length(name) between 1 and 20)
    )
  );

-- 列级写权限：前端只能写 name / content / anonymous
-- 不能伪造 created_at / is_visible / id
revoke insert, update, delete on public.messages from anon;
grant select on public.messages to anon;
grant insert (name, content, anonymous) on public.messages to anon;
grant usage, select on sequence public.messages_id_seq to anon;
```

3. 打开 **Project Settings → API**，复制 `Project URL` 与 `anon public key`。
4. 填入 `source/_data/body-end.njk`：

```js
window.__SURREAL_MESSAGE__ = {
  supabaseUrl: "https://你的项目.supabase.co",
  supabaseAnonKey: "你的 anon public key",
  table: "messages",
  maxLength: 500
};
```

5. 重新 `npx hexo clean && npx hexo deploy` 即可让所有访客共享留言。

### 一键写入配置并部署（推荐）

先在 Supabase SQL Editor 执行 [`tools/supabase-message-board.sql`](tools/supabase-message-board.sql)，然后在本机项目根目录运行：

```powershell
powershell -File tools/set-message-board.ps1 `
  -SupabaseUrl "https://你的项目.supabase.co" `
  -AnonKey "你的 anon public key"
```

脚本会：

1. 校验 URL 格式，并解码 JWT 角色；发现 `service_role` 会直接拒绝写入；
2. 把 URL / anon public key 写入 `source/_data/body-end.njk`（不会回显 key）；
3. 请求一次 Supabase REST，确认 `messages` 表可读；
4. 执行 `hexo clean/generate/deploy`。

如果不想让 key 出现在命令历史，可以先保存到本地文件（已加入 `.gitignore`）：

```powershell
Set-Content -Path .supabase-anon.txt -Value "你的 anon public key" -Encoding utf8
powershell -File tools/set-message-board.ps1 `
  -SupabaseUrl "https://你的项目.supabase.co" `
  -AnonKeyFile ".supabase-anon.txt"
Remove-Item .supabase-anon.txt
```

> VPN/代理未开启时，可加 `-SkipDeploy` 只写入配置，之后手动运行 `tools/deploy.ps1`。

### 安全层（已启用）

留言板的写入已从「前端直接 REST」切换为 Edge Function 代理，并启用 Turnstile 与 IP 限流：

```powershell
# 1) 建限流表 + RPC（在切换前执行）
npx supabase db query --linked --project-ref <项目ref> -f tools/supabase-message-guard-schema.sql

# 2) 部署 Edge Function（Turnstile 校验 + IP 限流 + service role 写入）
npx supabase functions deploy message-guard --project-ref <项目ref>

# 3) 关闭 anon 直接 insert（函数部署、前端上线后执行）
npx supabase db query --linked --project-ref <项目ref> -f tools/supabase-message-guard-lockdown.sql
```

- **Turnstile**：前端使用公开 Site Key；Secret Key 只存在于 Supabase 函数环境变量 `TURNSTILE_SECRET_KEY`。
- **限流**：同一 IP 10 分钟内最多 5 条，由 `check_message_rate` RPC 持久化计数。
- **权限**：`anon` 直接 insert 已被撤销（返回 401），所有写入必须经过 Edge Function；`service_role` 只存在于函数运行环境，不在前端。
- **前端配置**：`source/_data/body-end.njk` 的 `turnstileSiteKey`；留言页会动态加载 Turnstile 并按需渲染。
- Edge Function 源码：[supabase/functions/message-guard/index.ts](supabase/functions/message-guard/index.ts)。

> **安全边界**：前端只能使用 anon public key（配合 RLS 才是安全的）；`service_role` key 可以绕过 RLS，绝不能出现在任何前端文件或 GitHub 仓库中。不要把 `service_role` / `TURNSTILE_SECRET_KEY` 发到聊天里。
>
> **内容管理**：不当留言可在 Supabase Table Editor 中把 `is_visible` 改为 `false` 隐藏。
>
> 详细的安全评估与留档见 [docs/message-board-security-plan.md](docs/message-board-security-plan.md)。

## 常用命令

```bash
# 首次克隆后安装依赖
npm install

# 新建文章（在 source/_posts/ 下生成 Markdown 文件）
```

## 配置要点

- `_config.yml` 中 `url: https://nosferatuxada.github.io/blog` 与 `root: /blog/` 必须和仓库访问路径一致，否则 CSS、图片等静态资源会 404。
- 首页已移除 `hexo-generator-index`，改为静态页面；若以后恢复文章列表首页，可重新安装该插件并删除 `source/index.md` 中的落地页内容。
- 主题风格由 `source/_data/variables.styl`（色板）和 `source/_data/styles.styl`（布局/装饰）共同控制，升级 NexT 不会丢失。
- 作者窗口通过 `custom_file_path.sidebar` 注入，默认作者/统计块已隐藏。

## 关于网络代理

本机直连 `github.com` 不稳定，但 `api.github.com` 正常。部署时如果 `hexo deploy` 卡住或报连接失败，请先开启 VPN（本机提供 SOCKS5 代理 `127.0.0.1:1080`），然后在 PowerShell 中设置代理后再部署：

```powershell
$env:HTTPS_PROXY = 'socks5h://127.0.0.1:1080'
$env:HTTP_PROXY  = 'socks5h://127.0.0.1:1080'
npx hexo clean; npx hexo deploy
```

`tools/deploy.ps1` 已内置这一步：

```powershell
# 默认使用 socks5h://127.0.0.1:1080
powershell -File tools/deploy.ps1

# 代理端口不同可传参
powershell -File tools/deploy.ps1 -Proxy "socks5h://127.0.0.1:7890"
```
