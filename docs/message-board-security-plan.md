# 留言板功能｜制作前留档（安全与方案评估）

- 留档日期：2026-10-29
- 当前线上版本：`d802ed9`（含 Surreal 主题、波场背景、公告时间轴、最新公告弹窗）
- 本文件在编码/部署前写入，记录平台选择、安全边界、数据模型与验证计划。

## 一、平台选择与安全评估

| 方案 | 免费额度 | 数据模型 | 匿名留言适配 | 安全边界 | 结论 |
| --- | --- | --- | --- | --- | --- |
| **Supabase**（Postgres + REST + RLS） | 免费项目，数据库/流量额度足够个人博客 | 可自定义表结构，完全匹配 content / name / anonymous | 原生 boolean 字段，无 hack | 前端只放 anon public key；服务端 RLS 控制读写；service_role key 永不进前端 | **采用** |
| Waline（Vercel + Neon/LeanCloud） | 免费额度可用 | 评论字段固定，匿名需借用空昵称表达 | 需要绕开字段限制，且要自建评论 UI | 较成熟的反垃圾/审核生态 | 备选 |
| Twikoo（Vercel + MongoDB） | 免费额度可用 | 评论字段固定 | 同样缺少独立匿名字段 | 自带管理面板 | 备选 |
| LeanCloud 直连 | 有免费额度 | 可用 Class | 可自定义 | 前端暴露 AppID/AppKey，类权限配置要求较高 | 不采用 |

选择理由：本项目需求是**自定义表单 + 独立 anonymous 字段 + 自定义 Surreal UI**，Supabase 的「匿名 key + RLS + REST」最贴合，且不需要自己写服务器。

## 二、安全设计（重点）

1. **前端只使用 anon public key**
   - anon key 设计上可公开；权限由 RLS 决定。
   - `service_role` key 拥有绕过 RLS 的权限，**绝不能**写入 `body-end.njk` 或任何前端文件。
2. **RLS（行级安全）**
   - 表 `messages` 开启 RLS；
   - 所有人只读 `is_visible = true` 的留言；
   - 匿名角色只允许 `insert`，且写入受 `content` / `name` 长度约束；
   - 不开放 update / delete 给前端。
3. **字段约束**
   - content 1–500 字符；name 最多 20 字符；
   - anonymous = true 时 name 必须为空；anonymous = false 时 name 必须非空；
   - 采用 **列级 insert 权限**：匿名角色只能写 name / content / anonymous，不能伪造 id、created_at 或 is_visible。
4. **XSS 防护**
   - 留言渲染全部使用 `textContent`，禁止把用户内容拼进 `innerHTML`；
   - 内容使用 `white-space: pre-wrap` 保留换行，避免富文本注入。
5. **滥用与垃圾留言**
   - 前端：提交按钮防重点击、10 秒本地冷却、隐藏蜜罐字段；
   - 服务端（建议上线前补）：Supabase Edge Function + Cloudflare Turnstile 验证，或使用 Supabase Auth 匿名登录 + 每用户频率限制；
   - 内容层：`is_visible` 字段供站主在 Supabase Table Editor 中隐藏不当留言。
6. **数据最小化**
   - 不收集邮箱、IP、User-Agent；仅 name（可选）、content、anonymous、created_at。
   - 留言默认公开，页面明确提示用户不要填写隐私信息。
7. **供应链安全**
   - 不引入第三方前端 SDK/CDN；使用原生 fetch 调 Supabase REST；
   - 所有脚本自托管、defer 加载。
8. **演示模式隔离**
   - 未配置 Supabase 时，数据只写当前浏览器 `localStorage`，页面显示「演示模式」提示；
   - 不会把演示数据当成线上共享数据，也不会伪造「已发布到全站」。

## 三、数据模型（Supabase SQL）

```sql
create table if not exists public.messages (
  id bigint generated by default as identity primary key,
  name text,
  content text not null check (char_length(content) between 1 and 500),
  anonymous boolean not null default true,
  is_visible boolean not null default true,
  created_at timestamptz not null default now()
);

alter table public.messages enable row level security;

create policy "public can read visible messages"
  on public.messages for select
  using (is_visible = true);

create policy "visitors can insert messages"
  on public.messages for insert
  to anon
  with check (
    char_length(content) between 1 and 500
    and (
      (anonymous = true and name is null)
      or (anonymous = false and name is not null and char_length(name) between 1 and 20)
    )
  );

-- 列级写权限：前端只能写 name / content / anonymous
-- 不能伪造 created_at / is_visible / id
revoke insert, update, delete on public.messages from anon;
grant select on public.messages to anon;
grant insert (name, content, anonymous) on public.messages to anon;
grant usage, select on sequence public.messages_id_seq to anon;
```

## 四、前端结构规划

- 首页第三栏：标题「留言板」→ `/message/`
- 独立页面：`source/message/index.html`（html 页面，避免 Markdown 把缩进表单渲染成代码块）
- 逻辑：`source/js/message-board.js`
- 样式：`source/_data/styles.styl` 追加
- 配置：`source/_data/body-end.njk` 中 `window.__SURREAL_MESSAGE__`
- 与现有功能隔离：
  - 波场背景：`canvas.waves-bg`，z-index -2，不受影响；
  - 公告弹窗：独立 `#surreal-announcement`；留言页将跳过自动弹窗，避免遮挡表单；
  - 留言板：`#surreal-message` 内部作用域，独立 IIFE，无全局变量冲突。
